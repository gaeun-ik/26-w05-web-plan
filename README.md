# 26-w05-web-plan

5주차 실습② — **보안회사 원페이지 웹사이트 (Plan 기반 제작)**

방금 인라인으로 만든 것과 **동일한 요구사항**의 보안회사 웹사이트를, 이번엔 GitHub Copilot **Plan 모드**로 계획을 먼저 세운 뒤 **Start Implementation**으로 Agent에게 실행을 넘겨 완성하는 실습입니다.

## 시작하기

1. 이 저장소를 **Fork**
2. Fork한 저장소를 로컬에 **Clone**
3. [`guide.md`](./guide.md)를 따라 순서대로 진행

## 만들 결과물 (지난 실습과 동일)

```
nav (앵커링크: Hero / Services / About / Contact)
 └─ hero (회사 슬로건 + 버튼)
 └─ services (서비스 카드 3개, 각 카드에 "자세히 보기" 링크)
 └─ about (회사 소개)
 └─ contact/footer (연락처)
```

파일 구성: `index.html` / `style.css` / `script.js`

## 오늘 쓰는 방식

```
[Plan] 계획 세우기 (코드 변경 없음)
    ↓ "Start Implementation" 클릭
[Agent] 계획대로 파일 생성·수정 (실행)
```

### 📝 프레임워크 비교 소감 (인라인 vs Plan 상세 분석)

- **인라인(Inline) 방식:** 코드를 작성하면서 떠오른 아이디어를 즉시 반영할 수 있어 초기 구현 속도가 빨랐습니다. 다만 명세와 사전 계획이 충분하지 않으면 전체 구조를 일관되게 관리하기 어렵고, 예외 상황이나 버그를 미리 고려하지 못해 수정이 반복될 수 있다는 한계가 있었습니다.
- **Plan 방식:** 개발 전에 요구사항과 명세를 정리하고 전체 구조와 작업 순서를 계획한 뒤 구현하므로, 불필요한 코드 생성을 줄이고 중요한 요구사항을 빠뜨리지 않는 데 도움이 되었습니다. 계획을 바탕으로 단계별로 진행해 오작동 가능성을 낮추고, 결과물의 일관성과 프로젝트 완성도를 높이는 데 더 효과적이었습니다.
